LiveX היא אפליקציית Windows לניהול שידורים חיים ב-TikTok LIVE, ‏YouTube LIVE, ‏Kick ו-Twitch, יחד עם שרת רישוי/חשבונות ואתר.

```
app/      אפליקציית Windows (Electron 44) — ממשק, מודולים, Overlays, TTS, חיבורי פלטפורמות, עדכונים
server/   שרת LiveX (Node 22 + SQLite) — משתמשים, רכישות, רישיונות, קודי הפעלה חד-פעמיים, מכשירים, עדכונים, AI TTS
server/web האתר הרשמי — הרשמה, התחברות, מחירים, תשלום, אזור אישי, העברת רישיון
```

## הפעלה מקומית (פיתוח)

```bash
cd server && npm install && npm run keys     # יוצר מפתחות שרת + כותב את המפתחות הציבוריים ל-app/config
npm start                                    # http://127.0.0.1:8787  (אתר + API)
cd ../app && npm install && npm start        # האפליקציה
```

בפיתוח: תשלומים במצב **Sandbox** (מסומן בבירור, ללא חיוב) ומיילים נשמרים ב-`server/data/outbox/` כש-SMTP לא מוגדר. שני המצבים **נחסמים** כש-`NODE_ENV=production`.

## בניית קובץ ההתקנה

```bash
cd app
npm run icons      # (פעם אחת) אייקון + תמונת אשף ההתקנה
npm run dist:win   # release/LiveX-Setup-<version>.exe
```

דורש `makensis` (Linux: ‏`apt install nsis`, ‏Windows: ‏`choco install nsis`). לא נדרש Wine — האייקון ופרטי הגרסה מוטמעים ב-`LiveX.exe` ב-JS טהור (`scripts/after-pack.js`). ה-CI ב-`.github/workflows/ci.yml` מריץ בדיקות ובונה את המתקין על Windows.

ההתקנה: למשתמש הנוכחי (ללא הרשאות מנהל), עברית/אנגלית, קיצורי דרך, הסרה מלוח הבקרה. הגדרות המשתמש ב-`%APPDATA%\LiveX` נשמרות בעדכון ובהסרה.

## פריסה לייצור

1. שרת עם HTTPS (reverse proxy כמו Caddy/nginx) → `server/.env` לפי `server/.env.example`.
2. `PAYMENT_PROVIDER=stripe` + מפתחות Stripe, ו-Webhook ל-`https://<domain>/api/payments/webhook/stripe` (אירוע `checkout.session.completed`).
3. SMTP לשליחת קודי הפעלה, אימות דוא"ל, איפוס סיסמה ואישור העברה.
4. `LIVEX_API_BASE=https://<domain> npm run keys` בתיקיית server → בניית האפליקציה מחדש (המפתחות הציבוריים והכתובת נצרבים בבנייה). **שמור את `server/keys/` בגיבוי מאובטח** — בלעדיהם לא ניתן לאמת רישיונות קיימים.
5. Docker: `server/Dockerfile` (volumes: ‏`data`, ‏`keys`, ‏`releases`).

ניהול: `npm run admin -- revoke <LICENSE_ID> [reason]`, ‏`npm run admin -- mark-paid <ORDER_ID>`, ‏`npm run admin -- user <email>`; או API תחת `/api/admin` עם `ADMIN_TOKEN`.
פרסום עדכון: `npm run publish-release -- <LiveX-Setup.exe> <x.y.z> "notes"` (חותם את המניפסט ב-Ed25519).

## אבטחת האפליקציה

Context Isolation, ‏`sandbox: true`, ‏Node Integration כבוי, Preload עם רשימת ערוצים סגורה, אימות שולח בכל IPC (רק הדף שלנו), CSP קשיח, חסימת ניווט/חלונות חדשים, הרשאות רק למיקרופון (Voice Studio), DevTools כבוי בגרסה ארוזה, Electron Fuses (ללא RunAsNode / ‏NODE_OPTIONS / ‏inspect, אימות שלמות ASAR, טעינה רק מ-ASAR). ‏Refresh token, מפתחות פלטפורמות של המשתמש ו-Lease נשמרים מוצפנים ב-DPAPI. אין סודות שרת באפליקציה — רק שני מפתחות ציבוריים.

## עדכונים

מניפסט חתום Ed25519 (מפתח נפרד מהטוקנים) → אימות חתימה באפליקציה → הורדה מאותו שרת בלבד → בדיקת גודל + SHA-512 → בדיקת Authenticode (חובה אם `requireAuthenticode` במניפסט) → הרצת המתקין. ההגדרות נשמרות.

> **חתימת קוד Windows (Authenticode):** קובץ ההתקנה לא חתום בתעודת Code Signing (נדרשת תעודה מסחרית). ללא חתימה Windows SmartScreen יציג אזהרה. לאחר רכישת תעודה: חתום את `LiveX.exe` ואת המתקין והגדר `requireAuthenticode: true` במניפסט.

## חשבונות רשתות (Social Accounts) — התחברות רשמית (OAuth)

במסך **חשבונות רשתות** המשתמש לוחץ **Connect** → נפתח דף ההתחברות הרשמי של הפלטפורמה **בדפדפן של המשתמש** → בוחר חשבון ומאשר הרשאות → חוזר ל-LiveX והחשבון מוצג כ-**מחובר** (תמונת פרופיל, שם משתמש, פלטפורמה, סטטוס, תאריך חיבור אחרון, כפתורי Disconnect / Reconnect).

איך זה מאובטח:
- **LiveX לא רואה ולא שומרת סיסמאות** — ההתחברות קורית באתר של הפלטפורמה.
- ה-**Client Secret** של כל פלטפורמה נשמר **רק בשרת LiveX** (משתני `OAUTH_*`), אף פעם לא באפליקציה.
- הבקשה מוגנת ב-`state` חד-פעמי (מגובב בשרת) ו-**PKCE** (‏YouTube/Google, Kick); קישור התחברות שכבר נוצל או שפג תוקפו (10 דקות) נדחה.
- הטוקנים נמסרים לאפליקציה **פעם אחת** ונמחקים מהשרת; באפליקציה הם נשמרים **מוצפנים** (Windows DPAPI דרך safeStorage), בנפרד לכל משתמש LiveX. הם לא מגיעים לממשק, ולא נכתבים ללוגים.
- **Refresh Tokens**: טוקן שפג תוקפו מחודש אוטומטית דרך השרת. אם הפלטפורמה ביטלה את ההרשאה → הסטטוס הופך ל"נדרש חיבור מחדש".
- **Disconnect** מבטל את ההרשאה גם אצל הפלטפורמה (revoke) ומוחק את הטוקנים מהמחשב.

הגדרה בשרת (פעם אחת לכל פלטפורמה): רושמים אפליקציה בפורטל המפתחים, מגדירים Redirect URI ‏`https://<השרת>/api/oauth/callback/<platform>` וממלאים ב-`.env`:

| פלטפורמה | פורטל מפתחים | Redirect URI | משתנים | מה החיבור נותן |
|---|---|---|---|---|
| YouTube | Google Cloud Console → OAuth client (Web) + YouTube Data API v3 | `/api/oauth/callback/youtube` | `OAUTH_GOOGLE_CLIENT_ID/SECRET` | צ׳אט, Super Chat וחברויות של השידור שלך, **ושליחת הודעות בצ׳אט** — בלי מפתח API |
| Twitch | dev.twitch.tv → Applications | `/api/oauth/callback/twitch` | `OAUTH_TWITCH_CLIENT_ID/SECRET` | קריאה וכתיבה בצ׳אט (הבוט עונה) — בלי להעתיק טוקן |
| Kick | kick.com → Settings → Developer | `/api/oauth/callback/kick` | `OAUTH_KICK_CLIENT_ID/SECRET` | שליחת הודעות דרך ה-API הרשמי; פרופיל |
| TikTok | developers.tiktok.com → Login Kit | `/api/oauth/callback/tiktok` | `OAUTH_TIKTOK_CLIENT_ID/SECRET` | קישור פרופיל (שם ותמונה). אירועי LIVE: אין להם API ציבורי — עדיין דרך ספק (מסך חיבורים) |
| Discord | discord.com/developers → OAuth2 | `/api/oauth/callback/discord` | `OAUTH_DISCORD_CLIENT_ID/SECRET` | Webhook לערוץ שבחרת (הודעת "עליתי לשידור", לוח שידורים) |

פלטפורמה שלא הוגדרה בשרת מוצגת במסך כ"ההתחברות עוד לא הוגדרה בשרת" — בלי הצלחה מזויפת. מסך **חיבורים** הישן נשאר כחלופה ידנית (מפתח API / שם ערוץ), ושדותיו הופכים לאופציונליים כשהחשבון מחובר.

## צ׳אט פרטי עם זוכה בהגרלה

כשנבחר זוכה, LiveX פותחת **חדר צ׳אט פרטי** בשרת ומפרסמת קישור בצ׳אט של השידור. הקישור עצמו לא סודי: כדי להיכנס, הזוכה מתחבר/ת עם **חשבון הפלטפורמה שבה זכה/תה** (התחברות רשמית, הרשאות מינימליות), והשרת בודק שזה בדיוק החשבון שזכה. כל אחד אחר נדחה.

| פלטפורמה | איך מזהים את הזוכה |
|---|---|
| Twitch | מזהה משתמש (או ‎@login) |
| Kick | מזהה משתמש (או ‎@username) |
| YouTube | מזהה ערוץ (לא שם תצוגה, כי שמות כאלה לא ייחודיים) |
| TikTok | ‎@username (דורש את ההרשאה `user.info.profile` באפליקציית TikTok) |

- אצל היוצר/ת השיחה נפתחת **בחלון נפרד שמוגן מצילום מסך** (`setContentProtection`). ב-Windows 10 (2004 ומעלה) וב-Windows 11 החלון לא מופיע ב-OBS (Display/Window Capture), בשיתוף מסך או בצילומי מסך. ההודעות לא נשלחות אף פעם ל-Overlays, להקראה, ליומן הפעילות או ללוגים.
- טוקן הפלטפורמה של הזוכה מבוטל מיד אחרי הבדיקה ולא נשמר. הזוכה מקבל/ת עוגייה (HttpOnly) לחדר הזה בלבד.
- ההודעות מוצפנות בשרת (AES-256-GCM). סגירת הצ׳אט, או תום 7 ימים, מוחקת את כל ההודעות והקישור מפסיק לעבוד.
- דורש LiveX PRO. אם אין לפלטפורמה הרשאת כתיבה בצ׳אט (למשל TikTok), הודעת הזכייה נרשמת כ"לא נשלחה", והקישור זמין להעתקה בחלון הצ׳אט.

**איך הקישור מגיע לזוכה (גם ב-TikTok):**
- **קוד QR בשידור** (אוטומציה מובנית, מופעלת כברירת מחדל): מיד אחרי ההגרלה, ה-Overlay של ההגרלה מציג "‎@user זכית!" עם קוד QR והקישור הפרטי למשך 2 דקות. כשהזוכה מאשר/ת, הכרטיס מתחלף ל-"✓ ‎@user אישר/ה את הזכייה!", ונשלחת התראה לשולחן העבודה בלי תוכן הודעות. אפשר להציג את הקוד שוב מכפתור "QR בשידור" במסך ההגרלה. זה בטוח להציג, כי רק החשבון שזכה יכול להיכנס. קוד ה-QR נוצר במחשב עצמו, בלי שירות חיצוני.
- **"הודעה פרטית ב-TikTok / Kick / Twitch"**: הכפתור מעתיק הודעה מוכנה עם הקישור ("היי, זכית בהגרלה אצל {שם היוצר/ת}! …") ופותח את הפרופיל של הזוכה בדפדפן, ונשאר רק להדביק בהודעה פרטית. אף פלטפורמה לא מאפשרת לתוכנה לשלוח הודעה פרטית למשתמש שלא פנה קודם. ה-Business Messaging API של TikTok מאפשר רק לענות למשתמש שכתב ראשון, בתוך 48 שעות. ב-TikTok גם אי אפשר לכתוב בצ׳אט של הלייב.

**זוכה שלא נמצא:** אם הזוכה לא מגיב/ה, לוחצים במסך ההגרלה **"לא נמצא — העברת הפרס"**:
1. הזוכה מסומן/ת "לא נמצא/ה".
2. הצ׳אט הפרטי שלו/ה נסגר, ובדף שלו/ה כתוב שהפרס הועבר.
3. מתבצעת הגרלה חדשה בין המשתתפים שנשארו. זוכה שסומן/ה "לא נמצא/ה" לא יכול/ה לזכות שוב באותה הגרלה.
4. הזוכה החדש/ה מקבל/ת צ׳אט פרטי והודעה בצ׳אט שהפרס עבר אליו/ה.

אפשר להעביר את הפרס **רק אם הזוכה לא אישר/ה** בצ׳אט הפרטי. מי שהתחבר/ה ואישר/ה שומר/ת על הפרס, והשרת אוכף את זה (`WINNER_CONFIRMED`). אם לא נשארו משתתפים, שום דבר לא משתנה.

## אוטומציות מובנות (נעולות)

10 אוטומציות מגיעות עם LiveX: צ׳אט פרטי לזוכה בהגרלה, קוד QR לזוכה בשידור, תודה לעוקבים חדשים, תודה על מתנות, תודה למנויים, תודה על Super Chat ו-Bits, ברכה לריידים, חגיגת הגעה ליעד, אתגר שהושלם, והטיימר הסתיים. **אי אפשר למחוק או לערוך אותן**, גם לא דרך ה-API (`LOCKED`). אפשר רק להפעיל או לכבות כל אחת, ולראות תצוגה מקדימה של ההודעה (שלא נשלחת). הן מגיבות רק לאירועים אמיתיים (התראות בדיקה לא מפעילות אותן), יש להן הגבלת תדירות נגד הצפה, והן כתובות בשפת האפליקציה.

## קולות ElevenLabs

ב-**Voice Studio** מחברים את חשבון ה-elevenlabs.io של היוצר/ת. יוצרים מפתח API בכתובת elevenlabs.io/app/settings/api-keys, עם הרשאות Voices ו-Text to Speech, ומדביקים אותו פעם אחת בתוכנה. המפתח נשלח לשרת LiveX ונשמר שם מוצפן (AES-256-GCM). האפליקציה לא שומרת אותו, והוא לא נכתב ללוגים. כל הקריאות ל-ElevenLabs עוברות דרך השרת.

- **הקולות שלי:** כל הקולות בחשבון ה-ElevenLabs.
- **ספריית ElevenLabs:** חיפוש לפי שם, שפה ומגדר, האזנה לדוגמה, ו"הוספה לקולות שלי" (`POST /v1/voices/add/{public_user_id}/{voice_id}`).
- **יצירת קול חדש:** מהקלטה או מקובץ (MP3, WAV, M4A, OGG או WebM), ב-Instant Voice Cloning בחשבון של היוצר/ת. דורש הצהרת הסכמה של בעל/ת הקול, שנשמרת בשרת.
- **מודל:** רשימת המודלים מגיעה מהחשבון (`GET /v1/models`). במצב "אוטומטי", לטקסט בעברית נבחר מודל שהחשבון מדווח שהוא תומך בעברית.
- **שגיאות ברורות:** מפתח שגוי (409, לא ניתוק מ-LiveX), קרדיטים שנגמרו (429) והרשאה חסרה.
- אם השרת מוגדר עם `ELEVENLABS_API_KEY` משלו, הוא משמש גיבוי ליוצר/ת בלי חשבון. במצב הזה מוצגים רק הקולות המובנים והקולות שהיוצר/ת עצמו/ה יצר/ה, ואף פעם לא קולות של יוצרים אחרים.

## TTS

קולות Windows (SAPI, כולל עברית אם מותקנת חבילת דיבור) מרונדרים ל-WAV ומושמעים בהתקן השמע שנבחר. תור, השהיה/המשך, דילוג, ניקוי, חסימת מילים (התאמה למילה שלמה), סינון פוגעני, הגבלת אורך, Overlay. ‏Voice Studio: פרופילים, תצוגה מקדימה, הקלטה/העלאה. קולות AI ושיבוט קול — דרך השרת בלבד (`ELEVENLABS_API_KEY`), עם בדיקת רישיון TTS בכל בקשה, ושיבוט רק עם הצהרת הסכמה מפורשת שנשמרת בשרת. כל עוד הספק לא הוגדר — מוצג "לא זמין".
